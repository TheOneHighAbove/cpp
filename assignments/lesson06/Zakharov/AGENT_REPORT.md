# Отчёт о работе coding agent

## Окружение

Для задания использован выданный `assignments/lesson06/agent.py`. Он подключался по
OpenAI-compatible API к локальному `llama-server`. Модель Qwen2.5-0.5B-Instruct Q4_K_M
была запущена под ожидаемым агентом псевдонимом `qwen38_27b`. Реальный API-ключ не
требовался, так как сервер был локальным. `.env`, `.venv/`, `build/`, модель и
исполняемые файлы в Git не добавлены.

## Хронология tool calls

Запуски делались короткими отдельными задачами: маленькая локальная модель не всегда
могла корректно составить многошаговый план.

| Этап | Tool call | Результат |
|---|---|---|
| Анализ | `echo ...` | Команда отклонена white list: `command echo not allowed`. |
| Анализ | `find . -maxdepth 2 -type f` | Windows `find.exe` не поддержал POSIX-аргументы, `exit_code=2`. |
| Анализ | `ls -R` | Получена структура проекта. |
| Анализ | `cat CMakeLists.txt`, `cat include/chat.hpp`, `cat src/chat.cpp`, `cat src/http_json_client.cpp`, `cat tests/model_chat_test.cpp` | Агент получил код основных целей и теста. |
| Конфигурация | `cmake -S . -B build` | После настройки PATH CMake нашёл MSVC и успешно создал build tree. |
| Сборка | `cmake --build build --config Debug` | Сборка успешна, но MSVC выдал `C4530`: exception handling без `/EHsc`. |
| Тесты | `ctest --test-dir build -C Debug --output-on-failure` | Пройден 1 из 1 теста. |
| Исправление | `cat CMakeLists.txt`, затем `write_file(CMakeLists.txt, ...)` | Агент ошибочно перезаписал файл одной строкой; изменение отклонено после `git diff`. |
| Проверка | `cmake --build build --config Debug` | После ручного минимального исправления все три цели собраны без `C4530`. |
| Проверка | `ctest --test-dir build -C Debug --output-on-failure` | Пройден 1 из 1 теста. |
| Code review | `cat include/config.hpp include/http_json_client.hpp src/main.cpp` | Прочитаны интерфейсы и CLI; итоговые замечания модели проверены вручную. |
| README | `cat README.md` | Первый запуск в Windows упал на UTF-8; повтор с UTF-8 прочитал файл. |
| README | `write_file(examples/http-request.json, ...)` | Незапрошенная запись вместо ответа; отклонена, файл восстановлен. |

Были также две неудачные попытки из-за окружения: в изолированном запуске CMake не
нашёл C++-компилятор, а после неполной конфигурации `cmake --build` не нашёл
`ALL_BUILD.vcxproj`. Это не ошибки исходного C++-проекта.

## Найденная и исправленная проблема

MSVC собирал код, но для функций с исключениями выдавал предупреждение `C4530`.
Принято только это минимальное изменение:

```diff
 if(MSVC)
+    target_compile_options(model_chat_core PUBLIC /EHsc)
     target_compile_options(model_chat PRIVATE /utf-8)
 endif()
```

`PUBLIC` задаёт ключ для самой библиотеки `model_chat_core` и передаёт его связанным
целям `model_chat` и `model_chat_test`. После изменения предупреждение исчезло, сборка и тест
прошли.

## Принятые и отклонённые предложения

Принято:

- добавить `/EHsc` для MSVC, так как замечание подтверждалось выводом компилятора и
  повторной сборкой.

Отклонено:

- полная перезапись `CMakeLists.txt`: агент удалил всю структуру CMake; нужна была только
  одна строка;
- утверждения об undefined behavior из-за `const` в `HttpJsonClient`: `post(...) const` корректно означает,
  что вызов не меняет состояние объекта; это не UB;
- утверждение, что тестовые helper-функции входят в production API, и что `main.cpp` отвечает за
  тесты: это не соответствует структуре проекта;
- незапрошенная перезапись `examples/http-request.json`: модель нарушила указание «не изменять
  файлы», а новое содержимое не было JSON.

## Ответы на вопросы

1. До первой успешной попытки сборки агент посмотрел дерево и прочитал CMake, ключевые
   заголовки, реализации и тест.
2. Информация о проблеме пришла из `stdout`/лога MSVC, который Python-программа вернула модели
   как результат tool call.
3. Содержимое проекта модель узнала только через разрешённые `ls` и `cat`; сама LLM не читает
   файловую систему.
4. Tool call — структурированный запрос модели на вызов описанной функции с аргументами; обычный
   текстовый ответ ничего на компьютере не запускает.
5. Результат нужно вернуть LLM, иначе она не узнает, выполнилась ли команда, и не сможет выбрать
   следующее действие.
6. Цикл нужен для чередования «решение → tool call → результат → новое решение» до завершения задачи.
7. Неограниченный shell позволил бы модели удалять или выводить файлы за пределы проекта,
   запускать сетевые и привилегированные команды, похищать секреты и необратимо портить рабочее
   окружение. Поэтому нужны white list, запрет shell-операторов, изоляция и проверка `git diff`.
